# ADR-0018：标签目录硬编码在代码，语气权重现场推导

- 状态：Proposed
- 日期：2026-11-02
- 决策者：仓库维护者
- 相关：[模块需求](../product/feedback/requirements.md)、[Prompt 设计](../design/feedback/prompt.md)、[API 契约](../design/platform/api-contract.md)、[ADR-0001](0001-rust-backend.md)

## 背景

教师录入反馈时按维度打标签（课堂表现、作业、知识点、进步、习惯），标签携带语气权重，用于约束生成措辞的强度。硬性要求：

- 标签集合是产品资产：v1 固定五个维度、17 个标签，教师不能自定义，也不做标签管理界面。
- 语气必须与标签一致：出现待改进标签时，措辞不得出现正向强化（[Prompt 设计](../design/feedback/prompt.md) 第 2、4 节）。
- 前端需要可枚举的标签与权重来渲染选择器，不能各自维护一份标签表。
- 反馈表已有 `knowledge_tags text[]`，模板生成代码已在消费它（#42/#43）。
- 不做什么：不做租户级标签定制、不做标签增删改的管理端、不做标签使用统计。

## 决策

1. 标签目录硬编码为领域层常量（`crates/domain/src/feedback/tags/model.rs`）：`TagDef { name, dimension, tone }`，顺序即选择器顺序。目录是唯一来源，不入库。
2. 目录通过只读接口 `GET /api/v1/feedback-tags` 暴露给前端；该接口不依赖租户上下文。
3. 写入时按目录校验：`knowledgeTags` 逐字匹配标签名（不做 trim），每个维度至多一个；未知标签返回 422 `VALIDATION_UNKNOWN_TAG`，同维度重复返回 422 `VALIDATION_TAG_CONFLICT`。
4. `tone` 现场推导，不落库：出现任一 `negative` 即 `negative`，否则出现 `positive` 即 `positive`，其余为 `neutral`。目录外标签（历史数据）不影响推导结果，也不会让读取接口失败。
5. 标签组合的继承按课次日期倒序取最近一次，同日按写入时间倒序，通过 `GET /api/v1/students/{id}/feedback-tags` 提供。

## 后果

### 正面

- 标签与话术、语气三者的唯一来源都在代码里，不依赖数据库状态，不会出现「库里标签改了但话术表没改」。
- 无迁移、无种子数据；新增标签走一次代码评审即可。
- tone 与标签天然一致，不需要额外的一致性校验。

### 负面 / 代价

- 新增或改名标签必须发版；运营无法自助调整。
- 历史数据若含目录外标签，读取侧只能忽略（写入侧已被拦下）。
- `knowledge_tags` 的语义被收窄为「内置标签名」，旧文档里「自由填写知识点标签」的说法作废。

### 风险与缓解

- 风险：同维度给了两个矛盾标签（既正面又待改进），话术自相矛盾。
  缓解：写入时按维度去重校验（`VALIDATION_TAG_CONFLICT`），并在目录接口中按维度分组。
- 风险：以后要做标签管理界面时，硬编码目录会成为阻碍。
  缓解：目录已收敛在单一模块内，迁移到表只需要替换取数实现；届时按“同一主题修订”更新本 ADR。
- 风险：前端硬编码标签表导致与后端漂移。
  缓解：目录接口是唯一契约来源，`packages/api-types` 由代码生成。

## 备选方案

| 方案 | 优点 | 缺点 | 未采用原因 |
| --- | --- | --- | --- |
| 存 `tags` 表 + 种子迁移 | 运营可改；接口与数据同构 | 需要迁移、种子与租户隔离策略；v1 没有管理界面，改表只能靠 SQL | 用不上管理能力，却引入迁移与一致性成本 |
| 复用 `feedback_templates.tag_preset` | 复用已有表，不新增结构 | 模板与标签是两个概念，混在一起后模板改版会误伤标签 | 语义不匹配 |
| `tone` 作为 `feedbacks` 列落库 | 查询与统计直接可用 | 与标签写入两处维护，易不一致；重算需要回填 | 推导成本极低，没有必要冗余 |
| 前端硬编码标签表 | 零后端改动 | 契约漂移；后端校验与前端展示会各说各话 | 与「后端是唯一来源」冲突 |
| 标签名做 trim 后再匹配 | 容忍前端脏数据 | 入库值与目录常量不再逐字一致，后续比对需要同样容错 | 标签名是标识而非自由文本，严格匹配更简单 |

## 验证方式

- 命令或检查项：`cargo test -p domain --lib`（tone 表驱动、目录唯一性、未知标签与同维度重复）；`cargo test -p api --test feedback_tags`（目录内容与 tone、未知标签 422、同维度重复 422、继承取最近课次、无历史返回空、跨租户 404）。
- 观察指标：目录接口返回 5 个维度 / 17 个标签；`feedbacks.knowledge_tags` 中不出现目录外标签。
- 复核时间：M1 录入退出条件达成后一次；若 v1 之后要做标签管理界面，重审本条。
