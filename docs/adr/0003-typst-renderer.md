# ADR-0003：反馈图片默认使用 typst 渲染

- 状态：Accepted
- 日期：2026-10-31
- 决策者：仓库维护者
- 相关：[ADR-0001](0001-rust-backend.md)、[反馈模块需求](../product/feedback/requirements.md)

## 背景

每次分享需要把反馈渲染成 1080×1440 PNG。内容为中文，含标题、若干段落、页脚，结构固定但排版质量直接影响家长观感。

约束：

- 后端是 Rust，不希望为了渲染引入第二套运行时。
- 中文断行、标点处理、中英混排不能有明显瑕疵。
- 渲染在后台任务中执行，可以接受百毫秒级开销。
- 排版样式需要反复调整，调整成本必须低。

- 不做什么：不渲染长文档、不做分页、不支持用户自定义版式。

## 决策

默认使用 **typst CLI 子进程**渲染，并通过 `Renderer` trait 隔离实现。

必须满足的规则：

1. `FeedbackView` 只含语义字段，不含坐标、字号、颜色等排版权息。
2. `Renderer` 返回 PNG 字节与尺寸，不返回文件路径。
3. 页面固定 1080pt × 1440pt，导出 `--ppi 72`，使 1pt = 1px。
4. 数据通过临时 JSON 文件传入，模板用 `json(sys.inputs.data)` 读取。
5. `--root` 固定在专用目录，`--font-path` 只包含 Noto Sans SC。
6. typst 版本在 Dockerfile 中锁死，升级需跑模板回归。
7. 调用放在 `spawn_blocking` 或独立 worker 中，不在 async 运行时内同步等待子进程。
8. 并发上限 2–3，单次超时 10 秒。
9. 缓存键为 `hash(renderer 名 + 模板版本 + view)`。
10. 备选实现通过 cargo feature 隔离，默认构建只包含 typst。

## 后果

### 正面

- 中文排版质量由经过验证的排版引擎保证，不需要自己实现断行与标点规则。
- 模板是 `.typ` 文件，调整配色、字号、间距不需要重新编译 Rust。
- SVG 与 cosmic-text 实现可以随时补上，业务代码零改动。

### 负面 / 代价

- 镜像增加 typst 二进制与字体，约 80MB。
- 每次渲染有 80–200ms 进程启动开销。
- 需要同时维护 Rust 与 Typst 两种语言，模板出问题时要跨语言排查。
- typst 库 API 仍在演进，只能依赖 CLI 参数契约，不能依赖 crate 内部接口。

### 风险与缓解

- 风险：模板改动导致渲染失败且影响面隐蔽。
  缓解：开发用预览端点；模板变更必须跑基准样本并人工过目。
- 风险：字体缺失导致中文变成方框。
  缓解：镜像内固定字体路径；测试断言输出非空白。
- 风险：typst 升级改变排版细节。
  缓解：版本锁死；升级作为独立变更并记录结果。

## 备选方案

| 方案 | 优点 | 缺点 | 未采用原因 |
| --- | --- | --- | --- |
| SVG 模板 + resvg | 纯 crate、5–20ms、SVG 可用浏览器检视 | 中文断行需自行实现，边界情况多 | 排版正确性由自己承担，风险更高 |
| cosmic-text + tiny-skia | 纯 Rust、排版成熟 | 布局代码量大，调试靠日志 | 开发成本高于收益 |
| chromiumoxide | HTML/CSS 还原度最高 | 镜像 300MB 以上，单次 200ms–1s | 过重，与单机部署目标冲突 |
| satori + Node sidecar | 生态现成 | 引入第二个运行时 | 违背 ADR-0001 的约束 |

## 验证方式

- 命令或检查项：渲染固定样本，断言 PNG 尺寸为 1080×1440 且非全白；采样若干像素确认有内容。
- 观察指标：单张渲染耗时、批量 15 张耗时、渲染失败率。
- 复核时间：M3 完成后一次；若设计复杂度显著上升，重新评估是否需要更强的引擎。
