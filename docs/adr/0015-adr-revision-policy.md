# ADR-0015：ADR 允许同主题修订并保持单一主题

- 状态：Accepted
- 日期：2026-10-31
- 决策者：仓库维护者
- 相关：[ADR 索引与流程](README.md)、[ADR-0014](0014-module-docs-layout.md)

## 背景

ADR 已累积到 14 条。文档组织主题在一天内连续新增了 0006、0012、0013、0014 四条，原因不是每次都有新决策，而是原规则只允许「推翻时新增」，没有定义同主题演进的处理方式：

- 目录微调、路径迁移、命名收敛都另开一条 ADR，同一主题被切成多份。
- 读者需要按编号回溯整条链，才能知道当前有效规则。
- 继续按此方式增长，ADR 会从决策记录退化为变更日志。

同时存在另一种风险：为了减少新增而把多个模块或多个独立决策塞进同一文件，导致 ADR 失去单一主题。

- 约束 1：ADR 必须保留历史，不能通过删文来「减少数量」。
- 约束 2：一个 ADR 只能回答一个问题，模块之间不混写。
- 不做什么：不做 ADR 自动合并工具，不删除已接受的旧 ADR。

## 决策

1. **同主题演进优先修订现有 ADR**：结论不变、只调整参数、路径、范围或补充兼容约束时，原地修改，并在文末追加「修订记录」。
2. **只有新主题或决策被推翻时才新增 ADR**：方向改变时新增一条，旧文标 `Superseded by NNNN`，不删除。
3. **一个 ADR 只记录一个决策或一个模块**：独立决策拆开；不把多个模块的取舍写进同一文件。
4. **主题索引作为修订入口**：`docs/adr/README.md` 维护「现行 / 历史」表，修订只针对现行条目，历史条目只读。
5. **修订必须追加而非重写**：保留原背景、原决策与原后果，修订记录写明日期、内容、原因与影响文档。

## 后果

### 正面

- 同一主题只有一个现行 ADR，读者不需要沿编号链回溯。
- 小改动不再制造新文件，ADR 数量随主题数增长，而不是随修改次数增长。
- 单一主题约束防止模块内容互相污染。

### 负面 / 代价

- 修订需要维护「修订记录」，比新增多一步。
- 同一 ADR 会同时包含原决策与后续修订，读者需要看修订日期。
- 主题索引需要随新增和取代同步更新。

### 风险与缓解

- 风险：以「修订」为名改写历史，抹掉原取舍。
  缓解：只追加修订记录，不重写原背景与决策；方向变化必须新增 ADR。
- 风险：一个 ADR 被继续塞入多个模块。
  缓解：主题索引按主题拆分；评审检查标题与内容是否只覆盖一个决策。
- 风险：修订后链接或索引失效。
  缓解：`bash scripts/check.sh docs` 校验链接与 ADR 索引。

## 备选方案

| 方案 | 优点 | 缺点 | 未采用原因 |
| --- | --- | --- | --- |
| 维持「只新增」 | 历史最完整，规则最简单 | 同主题膨胀，读者需回溯链条 | 正是当前问题 |
| 允许任意改写旧 ADR | 文件数最少 | 丢失历史取舍，无法审计 | 违背 ADR 目的 |
| 定期合并旧 ADR | 数量可控 | 合并本身产生新的大文件，边界争议多 | 成本高于收益 |

## 验证方式

- 命令或检查项：`bash scripts/check.sh docs`；同一主题不应出现两条 `Accepted` 的现行 ADR。
- 观察指标：新增 ADR 的数量与新增主题的数量是否一致。
- 复核时间：ADR 数量再次接近 20 条时。
