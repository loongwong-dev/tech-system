# 产品文档

按功能模块组织：每个模块一个目录，跨模块的平台规则单独成目录。

- **类型**：项目需求

## 结构

```text
product/
├── platform/           # 跨模块：定位、租户、权益、管理端、合规
└── feedback/           # 当前模块：课后反馈
    ├── requirements.md
    └── launch.md
```

后续新增模块时，在 `product/` 下新建同名目录，不把模块文档堆回根级。

## 文档

| 文档 | 内容 |
| --- | --- |
| [平台需求](platform/README.md) | 定位、角色、租户与权益、管理端、非功能、指标、合规、里程碑 |
| [课后反馈模块](feedback/README.md) | 模块需求、冷启动计划与设计入口 |

## 命名

模块目录内的文件名固定为 `requirements.md`、`launch.md`，不再加模块前缀；目录已经表达模块归属。新增主题时先在模块的 `README.md` 登记，不在根级新建平铺文档。

## 边界

- 需求变更先改对应模块目录，再改代码。
- 数据结构与接口字段不在本目录定义，见 [设计文档](../design/README.md)。
- 技术取舍的理由在 [ADR](../adr/README.md)。
