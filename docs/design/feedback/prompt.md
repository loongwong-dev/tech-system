# Prompt 与质量

反馈生成使用的输入结构、提示词约束、输出校验与回归流程。

- **类型**：项目设计
- **覆盖范围**：输入契约、提示词分层、硬约束、校验规则、模板兜底、金标集与回归。
- **不覆盖范围**：业务规则与状态机见 [模块需求](../../product/feedback/requirements.md)；模型供应商与价格、调用实现与并发控制见 [ADR-0001](../../adr/0001-rust-backend.md)。
- **状态**：已定，prompt 变更必须同步更新本文与金标集。

## 1. 输入契约

送给模型的结构化数据，**不含学生姓名**：

```json
{
  "grade": "初二",
  "subject": "数学",
  "tone": "negative",
  "tags": ["偶有走神", "部分未完成", "存在薄弱点"],
  "knowledgePoints": ["一元二次方程"],
  "notes": "今天讲判别式，前半节课听懂了，后面练习跟不上"
}
```

反馈卡片的学生姓名由模板单独渲染，正文不需要出现姓名。这既避免了把未成年人身份信息送进模型，也去掉了「让模型复述姓名」这个必然出错的环节。

`tone` 由标签权重推导，不由模型判断：出现任意待改进权重标签即为 `negative`，否则为 `positive` 或 `neutral`。

## 2. 提示词分层

| 层 | 内容 | 变化频率 |
| --- | --- | --- |
| System | 角色与六条硬约束 | 极低 |
| Few-shot | 2–3 条金标示例，按 `tone` 选组 | 低 |
| User | 第 1 节的结构化 JSON | 每次 |

硬约束与它防的失败模式一一对应：

| 约束 | 防的问题 |
| --- | --- |
| 只能使用输入中出现的事实，禁止补充具体事件、数字、时间 | 幻觉 |
| 禁止绝对化表述（最、第一、绝对、保证） | 误导与合规风险 |
| 禁止人格评价，只描述行为与表现 | 不可接受的评价性措辞 |
| 禁止承诺成绩提升 | 合规与纠纷 |
| 正文 80–200 字，必须有一句以「建议」开头的下步建议 | 结构与长度失控 |
| 语气由 `tone` 决定，待改进时不得使用「优秀」「非常」 | 语气与事实矛盾 |

## 3. 输出与校验

输出为**纯文本流式**，不做 JSON。消费端是家长，看到的必然是自然语言。

流式结束后执行校验：

| 检查 | 规则 | 失败动作 |
| --- | --- | --- |
| 事实一致 | 输出中的数字必须属于输入中的数字集合 | 重试一次，追加失败原因 |
| 长度 | 80–200 字 | 重试一次 |
| 结构 | 必须包含以「建议」开头的句子 | 重试一次 |
| 禁用词 | 命中绝对化用语、贬损词、承诺性表述 | 重试一次 |
| 语气 | `tone=negative` 时命中正向强化词 | 重试一次 |

第二次仍失败则返回错误，前端提示可切换为模板生成。**AI 不可用时教师必须仍能完成工作**，这是降级路径存在的唯一理由。

每次生成记录 `prompt_version`，便于回溯某条反馈由哪一版提示词产生。

## 4. 标签到话术

模板生成必须能独立工作，因此每个标签自带措辞。

| 标签 | 正面 | 中性 | 待改进 |
| --- | --- | --- | --- |
| 专注投入 / 偶有走神 | 课堂投入度高，能持续跟随讲解 | 课堂状态整体稳定 | 课堂注意力容易分散，需要提醒 |
| 按时完成 / 部分未完成 | 作业按时完成且质量较好 | 作业完成情况正常 | 作业有部分未完成 |
| 掌握扎实 / 存在薄弱点 | 对本节知识点掌握扎实 | 基本掌握本节内容 | 对「{知识点}」还存在薄弱环节 |
| 明显进步 / 需加强 | 相较之前有明显进步 | 保持稳定 | 还需要更多练习巩固 |

模板生成是「按语气权重选句子 → 拼接 → 追加下步建议」，永不幻觉，且零成本。

标签目录与语气权重以代码为准：`crates/domain/src/feedback/tags/model.rs` 的常量目录是唯一来源（五个维度、17 个标签），本表只描述按 `tone` 选取的措辞；新增或改名标签必须同时更新代码、本表与金标集，`tone` 由标签推导而非模型判断。

## 5. 金标集

30–50 条样本，覆盖五类场景，每类至少 5 条：

1. 全部正面
2. 全部待改进
3. 正负混合（最容易出现语气打架）
4. 知识点薄弱但态度好
5. 作业未交但课堂积极

每条包含：输入、人工期望输出、评分维度（事实一致性、语气得体、教培语境、长度、是否含建议）。

金标集与 prompt 同版本管理，放在仓库内，不散落在个人笔记里。

## 6. 回归流程

```text
改 prompt 或换模型 → 跑金标（自动规则校验通过率）→ 人工抽检 10 条
```

规则：

1. 通过率下降不得发布。
2. 人工抽检重点看语气是否失真，这是自动规则覆盖不到的部分。
3. 换模型必须重跑，即使供应商声称兼容。
4. 回归结果记录日期、版本与通过率，便于对比。

## 7. 模型选择原则

| 原则 | 说明 |
| --- | --- |
| 境内可用 | 避免个人信息出境的合规问题 |
| 支持流式 | 首字延迟决定教师是否等待 |
| 超时 20 秒 | 超时即降级到模板 |
| 质量优先 | 单次约 1k token，成本可忽略，不因省钱牺牲输出质量 |

具体供应商与单价在开通账号后确定，不写死在文档里。
