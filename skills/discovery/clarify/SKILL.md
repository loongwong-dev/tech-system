# Clarify

把“想要一个东西”变成“知道要做什么、不做什么、怎么算完成”。这个阶段**不写代码、不写 spec**。

## 先读

如果仓库里存在，按顺序读取：

1. `AGENTS.md`，至少第 0、1、2 节。
2. `README.md` 与 `docs/README.md`。
3. 与需求相关的现有文档、issue、ADR。
4. 当前行为对应的代码或配置。

读完后先用一句话复述你的理解，再开始提问。

## 问题树

按以下分支提问，不要只问“还有什么要求”：

| 分支 | 要确认的事实 |
| --- | --- |
| 问题 | 现在发生了什么？谁受影响？不做的代价是什么？ |
| 结果 | 完成后用户能做什么？如何观察到？ |
| 范围 | 必须包含什么？明确不包含什么？ |
| 约束 | 时间、兼容性、依赖、权限、平台限制？ |
| 验收 | 哪些条件可判定完成？用什么命令或场景验证？ |
| 风险 | 最可能失败的地方？如何回滚？ |
| 决策 | 哪些问题需要用户拍板，哪些可以按默认继续？ |

## 提问方式

- 每轮 3–5 个问题，按影响排序。
- 每个问题给出**推荐默认值**和一句理由，用户可以只回“默认”。
- 一次只问一个决策点，不把多个问题塞进一句话。
- 用户回答后，先复述结论，再问下一轮。
- 最多 3 轮；仍有关键未知项时，列出假设并请用户确认。

## 停止条件

满足任一即可停止：

- 问题树的关键分支都有答案，或明确标记为“以后决定”。
- 用户说“够了/按你的默认”。
- 连续一轮没有产生新的决策点。

## 输出：决策简报

```markdown
## 目标
一句话。

## 必须做
- ...

## 明确不做
- ...

## 约束
- ...

## 验收
- [ ] 可判定的条件（命令/场景）

## 假设
- 未确认但按此继续的假设。

## 待确认
- 仍需用户拍板的问题；没有则写“无”。
```

## 结束

- 简报确认后，建议用户运行 `/spec` 把它转成规格。
- 不要创建 issue、不要写代码、不要提交。
- 如果发现需求本身不应做，直接说明理由并停止。
