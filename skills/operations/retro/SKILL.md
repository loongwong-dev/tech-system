# Retro

复盘一次会话，改进**代理的运行环境**：导航、检查、规则、工具与信息获取。不是代码 review，也不是追责。

## 1. 收集证据

- 用户指定的会话或时间范围；未指定则用当前会话。
- 读取 `AGENTS.md`、`scripts/check.sh`、CI 配置、`docs/`。
- 查看实际发生的失败：命令报错、反复搜索、误改文件、漏跑检查、上下文耗尽。
- 没有证据的猜测不要写成建议。

## 2. 找改进点

按以下类别逐项检查：

| 类别 | 信号 | 优先动作 |
| --- | --- | --- |
| 导航 | 花很久才找到文件或入口 | 增加指针、索引或 README 链接 |
| 自动检查 | 代理犯了工具能发现的错 | 加检查、接入 CI，而不是写更多规则 |
| 规则 | `AGENTS.md` 有口号、重复或无效条款 | 删除、合并或改成可检查项 |
| 文档 | 同一事实多处维护、已过期 | 收敛到单一来源 |
| 工具成本 | 大量无效搜索、重复读大文件 | 提供脚本、索引或更精确的入口 |
| 信息获取 | 关键日志/状态拿不到 | 提供只读命令、日志或本地入口 |

## 3. 排序与输出

最多 5 条，按严重程度排序。每条包含：

```markdown
### 1. <问题一句话>
- 证据：会话中发生了什么
- 改动：具体文件/命令/规则
- 成本：低/中/高
- 预期效果：能防止哪类重复失败
```

只给建议，不自动修改。用户确认后再实施。

## 4. 判断标准

- **能自动检查的，不要写成规则**。机械性错误优先加 lint/check/CI。
- **能指向文件的，不要复制内容**。`AGENTS.md` 只放导航与硬约束。
- **没有观察到的失败，不提**。不要用“最佳实践”凑数。
- 一次最多改 3 项；优先改影响最大的。

## 结束

如果建议涉及规则或架构变化，提醒用户按 `AGENTS.md` 更新 `CHANGELOG.md` 并补 ADR。
